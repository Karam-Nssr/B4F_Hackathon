# دليل الواجهة الأمامية لمشروع InstaMall

هذا دليل عالي المستوى يشرح المشروع كما هو موجود اليوم، وليس تصوراً نظرياً لبنية مثالية. بدأ مجلد `web` من قالب TailAdmin، ثم أضيفت إليه واجهات InstaMall؛ لذلك ستجدون ميزات المتجر بجانب صفحات ومكوّنات عرض تجريبية من القالب.

> لا يسرد هذا الدليل مئات ملفات العرض التجريبي واحداً واحداً. يشرح وظيفة المجلدات، والملفات المحورية، وطريقة معرفة مكان أي ملف جديد.

## 1. الصورة العامة

الواجهة مبنية على **Next.js App Router** و**React** و**TypeScript**. تعرض ثلاثة أجزاء رئيسية:

- **واجهة المتجر:** تصفح المنتجات والمتاجر، السلة، الحساب والطلبات.
- **بوابة البائع:** إدارة منتجات المتجر وطلباته.
- **لوحة الإدارة:** نظرة عامة وإدارة المستخدمين والمتاجر، إلى جانب صفحات TailAdmin التجريبية.

الواجهة لا تحتوي قاعدة بيانات أو منطق خادم خاصاً بها. تتصل بخلفية منفصلة عبر عميل API في المتصفح. وجود صفحات TailAdmin التجريبية يعني أن بعض الشاشات أمثلة للقالب وليست ميزات مكتملة في InstaMall.

## 2. خريطة المجلدات

```text
web/
├── package.json                 # المكتبات وأوامر التشغيل والفحص والبناء
├── next.config.ts               # إعداد Next.js، إعادة كتابة /api، وتحويل الروابط القديمة
├── tsconfig.json                # TypeScript strict والاختصار @/* إلى src/*
├── eslint.config.mjs            # قواعد ESLint
├── .prettierrc                  # إعدادات التنسيق
├── .env.example                 # أسماء إعدادات الاتصال المطلوبة محلياً
├── public/                      # ملفات ثابتة تُقدَّم كما هي، مثل الصور
├── docs/                        # التوثيق ومواصفات التغييرات
└── src/
    ├── app/                     # المسارات والصفحات والـ layouts
    ├── components/              # مكوّنات الواجهة القابلة لإعادة الاستخدام
    ├── context/                 # الحالة المشتركة للتطبيق والثيم
    ├── hooks/                   # React hooks عامة
    ├── i18n/                    # إعداد اللغة والتنقل المحلي
    ├── icons/                   # مكوّنات الأيقونات وملف التصدير المشترك
    ├── layout/                  # هياكل وأجزاء TailAdmin
    ├── lib/                     # روابط المصادقة وعميل HTTP وموائمات API
    ├── messages/                # نصوص الواجهات حسب اللغة
    ├── mock/                    # مساحة مخصصة لبيانات العرض التجريبي
    ├── types/                   # أنواع بيانات الواجهة
    └── utils/                   # دوال مساعدة عامة
```

### أهم مجلدات `src`

| المجلد | وظيفته وما يوجد فيه |
|---|---|
| `app/` | نظام المسارات. كل `page.tsx` يعرض مساراً، و`layout.tsx` يضيف الهيكل المشترك للمسارات التابعة له. |
| `components/ui/` | أساسيات الواجهة مثل Button وInput وDialog وTable وToast. استخدم هذه المكوّنات قبل بناء عنصر عام جديد. |
| `components/common/` | عناصر مشتركة لا تخص مجالاً بعينه، مثل breadcrumb وحالات التحميل والخطأ. |
| `components/storefront/` | مكونات واجهة المتجر، مثل Navbar وFooter وبطاقة المنتج والشعار. |
| `components/admin/`, `components/shop/` | رؤوس وقوائم التنقل الخاصة بلوحتي الإدارة والبائع. |
| `components/main/` | وحدات الواجهة الأكبر؛ يضم لوحة ecommerce، التقويم، النماذج، الملف الشخصي والجداول، بالإضافة إلى دليل مستخدمي الإدارة. |
| `components/others/` | مكوّنات القالب الأخرى؛ منها بوابة المصادقة ومكوّنات الرسوم والعناصر التجريبية. المجلدان القديمان `auth/sign-in` و`auth/sign-up` يعودان لمكوّنات القالب؛ المسار النشط يستخدم `auth/auth-portal.tsx`. |
| `context/` | `instamall-store.tsx` يجمع حالة الجلسة والمنتجات والطلبات والسلة وإجراءاتها؛ و`theme-context.tsx` يدير الثيم. |
| `layout/` | هياكل TailAdmin الأصلية؛ قد لا تستخدمها مسارات InstaMall الحالية. لا تخلطها مع `app/` الذي يعرّف مسارات Next.js. |
| `lib/api/` | الاتصال بالـ API وتحويل بياناته قبل عرضها. |
| `i18n/`, `messages/` | إعداد `next-intl`، التنقل المترجم، وملفات النصوص `ar.json` و`en.json`. |
| `icons/` | أيقونات React؛ `index.tsx` يجمع التصديرات للاستخدام من `@/icons`. |
| `types/` | نماذج البيانات التي تستهلكها مكوّنات الواجهة. |
| `utils/` | دوال صغيرة مشتركة، مثل دمج Tailwind classes واستخراج الأحرف الأولى ورسائل الأخطاء. |

## 3. المسارات وكيفية قراءتها

كل المسارات داخل `src/app/[locale]/`. الرمز `[locale]` يعني أن المسار يعمل باللغة العربية أو الإنجليزية. المجلدات التي اسمها بين قوسين، مثل `(storefront)` و`(full-width-pages)`، تنظّم الملفات ولا تظهر في عنوان URL.

- `src/app/[locale]/(storefront)/`: `/`، `/stores`، `/cart`، `/orders` و`/account`. الـ layout هنا يجمع Navbar ومحتوى الصفحة وFooter.
- `src/app/[locale]/shop/`: لوحة البائع، المنتجات والطلبات.
- `src/app/[locale]/admin/`: لوحة الإدارة، المستخدمون والمتاجر، إضافة إلى صفحات القالب.
- `src/app/[locale]/(full-width-pages)/(auth)/signin/`: صفحة تسجيل الدخول والتسجيل المشتركة.

معنى ملفات المسار الشائعة:

- `page.tsx`: محتوى المسار.
- `layout.tsx`: الهيكل المشترك للمسار وأبنائه.
- `loading.tsx`: واجهة التحميل.
- `error.tsx`: معالجة أخطاء ذلك الجزء من المسارات.
- `not-found.tsx`: واجهة عدم العثور على المسار أو البيانات.
- `src/app/global-error.tsx`: واجهة احتياطية لأخطاء جذر التطبيق.

ملفات الصفحة والـ layout صغيرة قدر الإمكان؛ تركيب الواجهة وتفاصيلها تكون عادةً في `components/`.

## 4. الملفات المحورية وتدفق البيانات

```text
page/component
      ↓
useInstaMallStore()  ←→  context/instamall-store.tsx
      ↓
lib/api/instamall/index.ts
      ↓
lib/api/client.ts → /api/* → backend
      ↓
lib/api/instamall/mappers.ts → types/instamall.ts
```

- `src/app/[locale]/layout.tsx`: يضبط اللغة والاتجاه RTL/LTR والخطوط، ثم يركّب مزوّدي اللغة والثيم والحالة والتنبيهات.
- `src/context/instamall-store.tsx`: واجهة موحّدة للصفحات كي تقرأ الحالة وتستدعي إجراءات تسجيل الدخول والطلبات والمنتجات وغيرها. السلة حالياً حالة محلية في الواجهة وليست خدمة سلة مستقلة في الـ API.
- `src/lib/api/client.ts`: عميل HTTP مشترك مبني على `fetch` ويحوّل استجابات الخطأ إلى أخطاء قابلة للعرض.
- `src/lib/api/instamall/index.ts`: عمليات API الخاصة بـ InstaMall وإضافة رمز الجلسة عند الحاجة.
- `src/lib/api/instamall/types.ts`: أشكال البيانات القادمة من الخلفية (DTOs).
- `src/lib/api/instamall/mappers.ts`: يحوّل DTOs إلى النماذج التي تعرضها الواجهة.
- `src/lib/api/instamall/session.ts`: يقرأ ويحفظ رمز الجلسة وبيانات المستخدم في `localStorage` ويحدد عنوان API.
- `src/types/instamall.ts`: أنواع النماذج المستخدمة داخل مكونات الواجهة.
- `src/lib/auth-routes.ts`: روابط موحدة لتسجيل الدخول واختيار التسجيل للمشتري أو البائع.
- `src/proxy.ts`: توجيه اللغات عبر `next-intl`. أما `next.config.ts` فيحوّل طلبات `/api/*` إلى عنوان الخلفية، ويحتوي تحويلات روابط المصادقة القديمة.

## 5. التسجيل واللغات

- `/signin` يعرض تسجيل الدخول.
- `/signin?mode=signup` يعرض **رابطين منفصلين**: إنشاء حساب مشتري أو حساب بائع.
- الرابط يفتح النموذج المناسب عبر `accountType=buyer` أو `accountType=seller`؛ نوع الحساب لا يُختار داخل النموذج.
- `/auth` و`/signup` روابط قديمة تحوّلها إعدادات Next.js إلى المسار الموحد.
- `ar` هي اللغة الافتراضية، و`en` تستخدم بادئة `/en`. الترجمات ليست مكتملة في كل الواجهات؛ توجد نصوص عربية في بعض أقسام `en.json` وصفحات القالب.

ملفات المصادقة الأساسية:

- `src/components/others/auth/auth-portal.tsx`: حالات تسجيل الدخول، اختيار نوع الحساب، ونموذج التسجيل.
- `src/components/others/auth/auth-marketing-panel.tsx`: اللوحة التعريفية المرافقة للنموذج.
- `src/lib/auth-routes.ts`: مصدر روابط التسجيل حتى لا تتكرر صياغة المسارات في الـ Footer والروابط الأخرى.

## 6. المكونات والمكتبات المستخدمة

### مكونات المشروع

- واجهة المتجر: `StorefrontNavbar` و`StorefrontFooter` و`ProductCard` و`BrandLogo`.
- المصادقة: `AuthPortal` و`AuthMarketingPanel`.
- لوحتا الإدارة والبائع: `AdminHeader` و`AdminSidebar` و`ShopHeader` و`ShopSidebar`.
- الواجهات المشتركة: `components/ui/` مثل `Button` و`Input` و`Field` و`Card` و`Dialog` و`Sheet` و`Select` و`Combobox` و`Table` و`Tabs` و`Toast` و`Tooltip` و`Sidebar` وغيرها.

### المكتبات الأساسية

- **Next.js 16 / React 19 / TypeScript:** المسارات، الصفحات والمكونات.
- **Tailwind CSS 4:** التنسيق؛ الألوان والقياسات الخاصة بالمشروع في `src/app/globals.css`.
- **Base UI وCVA:** أساس عدد من مكونات `components/ui/` وأنماطها.
- **next-intl:** المسارات والترجمة.
- **react-hook-form وZod:** إدارة النماذج والتحقق من مدخلاتها.
- **TanStack Table:** جداول البيانات التفاعلية في الشاشات التي تحتاجها.
- **ApexCharts وFullCalendar وSwiper وflatpickr:** مكتبات مستخدمة في widgets وصفحات القالب.

تجدون قائمة الاعتمادات الكاملة وإصداراتها الحالية في `package.json`. ليست كل مكتبة مستخدمة في كل شاشة؛ بعضها موجود لدعم صفحات وعناصر قالب TailAdmin.

## 7. التسمية وما الذي ما زال يحتاج تحسيناً

النمط المقصود واضح: أسماء الملفات والمجلدات `kebab-case`، أسماء المكونات والأنواع `PascalCase`، والمتغيرات والدوال `camelCase`. في منطق InstaMall توجد أسماء وصفية مثل `currentUser` و`masterOrders` و`shopOverview`.

لكن الالتزام ليس كاملاً في كل المشروع: بعض صفحات ومكونات TailAdmin التجريبية ما زالت تستخدم تسميات عامة أو نصوصاً ثابتة، وبعض أقسام الإنجليزية غير مترجمة بالكامل. لذلك الإجابة الدقيقة: **التسمية معنوية في الأجزاء الأساسية التي لمسناها، لكنها ليست موحّدة بعد في كل الملفات**. يفضّل أن تكون أسماء متغيرات المجال كاملة وواضحة، وأن تبقى الأسماء القصيرة مثل `i` أو `prev` محصورة في callbacks الصغيرة.

## 8. أين أبدأ عند التعديل؟

1. لتغيير مسار، ابدأ بملفات `src/app/[locale]/...` ثم راجع الـ layout الأقرب.
2. لتغيير شكل متكرر، ابحث أولاً عن عنصر مناسب في `src/components/ui/` أو مجلد الميزة.
3. لتغيير البيانات، تتبّع `useInstaMallStore` إلى `src/lib/api/instamall/`؛ لا تجعل المكوّن يتعامل مع شكل DTO الخام.
4. للنصوص المترجمة، أضف المفتاح إلى ملفات اللغات المهيأة ولا تضع نصاً ثابتاً في منطقة مترجمة.
5. للتحقق، استخدم `npm run lint` ثم `npm run build` من مجلد `web`.

**ملاحظة:** توجد أزرار دخول تجريبية في بعض شاشات حراسة لوحتي الإدارة والبائع، كما توجد صفحات TailAdmin نموذجية. هذه ليست بديلاً عن مسارات المستخدم الإنتاجية، ويجب التحقق من ربط أي شاشة بميزة فعلية قبل اعتبارها جزءاً من تجربة InstaMall.
