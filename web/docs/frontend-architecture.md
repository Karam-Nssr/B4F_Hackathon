# التوثيق النهائي لبنية الواجهة الأمامية

يشرح هذا الدليل بنية مجلد `web` كما هي في المشروع: أين توجد الصفحات والمكونات، وكيف تنتقل البيانات من الواجهة إلى الخلفية، وما وظيفة الملفات المحورية. المشروع مبني على قالب TailAdmin أضيفت إليه واجهات InstaMall؛ لذلك يحتوي على ميزات المتجر ولوحتي البائع والإدارة، إلى جانب صفحات ومكونات عرض تجريبية للقالب.

> نطاق هذا الدليل هو `web` فقط. الواجهة عميل للـ API؛ قاعدة البيانات ومنطق الأعمال الخادمي موجودان في الخلفية المنفصلة.

## 1. ملخص سريع

- **Next.js App Router** ينشئ الصفحات من ملفات `page.tsx`، ويشارك الهياكل عبر `layout.tsx`.
- المسارات الأساسية: واجهة المتجر، بوابة البائع، ولوحة الإدارة.
- **React Context** في `context/instamall-store.tsx` يجمع حالة InstaMall وإجراءاتها المشتركة.
- طبقة `lib/api` تتصل بالخلفية وتحوّل بياناتها إلى نماذج مناسبة للواجهة.
- العربية هي اللغة الافتراضية، والواجهة تضبط اتجاه RTL حسب اللغة.
- مجلدات TailAdmin التجريبية ليست كلها ميزات مكتملة في InstaMall.

## 2. صورة تدفق البيانات

```text
مسار أو مكوّن React
        │ يقرأ البيانات ويطلب الإجراء
        ▼
useInstaMallStore()  ←  context/instamall-store.tsx
        │
        ▼
lib/api/instamall/index.ts  ── يستخدم ──  lib/api/client.ts
        │                                      │
        │                           طلب fetch إلى /api/*
        │                                      ▼
        │                              الخلفية المنفصلة
        │                                      │
        ◀──────── mappers.ts ◀──── استجابة DTO ┘
                     │
                     ▼
             types/instamall.ts
```

الصفحات لا تتعامل عادةً مع استجابة الخادم الخام. المعرّفات والحقول القادمة من الخلفية تُحوّل في `mappers.ts` إلى نماذج الواجهة، ثم تُعرض عبر الـ Context. السلة استثناء مقصود: حالتها محلية في الواجهة لأن الخلفية لا توفر لها نقطة API مستقلة.

## 4. المسارات والصفحات

تقع المسارات تحت `src/app/[locale]/`. `[locale]` جزء ديناميكي للغة. المجلدات المحاطة بأقواس مثل `(storefront)` هي **مجموعات تنظيمية** لا تظهر في عنوان URL.

| المسار/المجلد | ما يقدمه |
|---|---|
| `[locale]/layout.tsx` | الهيكل الجذري للغة: يضبط `lang` و`dir` والخطوط وملفات CSS، ثم يركّب مزوّدي اللغة والثيم والاتجاه والحالة والتنبيهات. |
| `[locale]/(storefront)/` | واجهة المشتري: الصفحة الرئيسية، المتاجر، السلة، الطلبات، الحساب. و`layout.tsx` يضيف شريط التنقل والتذييل. |
| `[locale]/shop/` | لوحة البائع وصفحتا المنتجات والطلبات، إضافة إلى صفحة النظرة العامة. |
| `[locale]/admin/` | نظرة عامة الإدارة وإدارة المستخدمين والمتاجر، مع صفحات القالب التجريبية ضمن مجموعات أخرى. |
| `[locale]/(full-width-pages)/(auth)/` | واجهات الدخول والتسجيل ذات التخطيط الكامل. |
| `[locale]/(full-width-pages)/(error-pages)/` | صفحات وأمثلة معالجة الأخطاء. |
| `app/global-error.tsx` | واجهة احتياطية لأخطاء جذر التطبيق. |
| `app/globals.css` | الأنماط العامة، رموز التصميم، إعداد الثيم الداكن، وقواعد تخصيص المكتبات. |

### معنى ملفات المسار الشائعة

- `page.tsx`: محتوى عنوان URL لذلك المسار.
- `layout.tsx`: غلاف مشترك للمسار والصفحات التابعة له.
- `loading.tsx`: واجهة التحميل أثناء جلب بيانات المسار.
- `error.tsx`: حدّ لمعالجة أخطاء ذلك الجزء من شجرة المسارات.
- `not-found.tsx`: واجهة عدم العثور على المسار أو المحتوى.

ليست هذه الملفات موجودة بالضرورة في كل مجلد؛ يُستخدم الملف عندما يحتاج ذلك الجزء من شجرة المسارات إلى السلوك المقابل.

### أمثلة على صفحات التطبيق الفعلية

- `app/[locale]/(storefront)/page.tsx`: الصفحة الرئيسية؛ تقرأ المنتجات والمتاجر من الحالة المشتركة، وتدير تصفية التصنيفات وتقسيم النتائج إلى صفحات.
- `app/[locale]/(storefront)/stores/page.tsx`: تصفح المتاجر.
- `app/[locale]/(storefront)/cart/page.tsx`: عرض السلة ومتابعة إتمام الطلب.
- `app/[locale]/(storefront)/orders/page.tsx`: عرض طلبات المشتري.
- `app/[locale]/(storefront)/account/page.tsx`: بيانات الحساب.
- `app/[locale]/shop/page.tsx`: لوحة البائع؛ تعرض الإحصاءات والأنشطة الحديثة، وتوصل أحداث الجداول بإجراءات الحالة المشتركة.
- `app/[locale]/shop/products/page.tsx` و`shop/orders/page.tsx`: صفحات إدارة منتجات وطلبات البائع.
- `app/[locale]/admin/page.tsx`: مؤشرات الإدارة والجداول الحديثة.
- `app/[locale]/admin/users/page.tsx` و`admin/shops/page.tsx`: إدارة المستخدمين والمتاجر.
- `app/[locale]/(full-width-pages)/(auth)/signin/page.tsx`: مدخل المصادقة. إعدادات `next.config.ts` توجّه الروابط القديمة `/auth` و`/signup` إلى المسار الموحد.

## 5. المكونات: أين توجد الواجهة؟

| المجلد | مسؤولية محتوياته |
|---|---|
| `components/ui/` | عناصر بناء عامة مثل الأزرار والحقول والجداول والنوافذ والقوائم والتنبيهات. ابدأ بها قبل إنشاء عنصر عام جديد. |
| `components/common/` | أجزاء مشتركة لا تخص مجالاً بعينه: حالات التحميل والخطأ، breadcrumb، ترقيم الجداول، وبطاقات العرض. |
| `components/storefront/` | رأس وتذييل المتجر، بطاقة المنتج، تفاصيل المنتج، الشعار وصورة المتجر. |
| `components/shop/` | رأس وقائمة تنقل البائع وجداول المنتجات والطلبات. |
| `components/admin/` | رأس وقائمة تنقل الإدارة وجداول الإدارة. |
| `components/main/` | وحدات أكبر للقالب ومناطق التطبيق، مثل لوحة البيانات ودليل مستخدمي الإدارة والنماذج والجداول والتقويم والملف الشخصي. |
| `components/others/` | بوابة المصادقة ورسوم وعناصر TailAdmin التجريبية. |
| `layout/` | عناصر هيكل TailAdmin العام، مثل رأس وقائمة لوحة القالب؛ لا يعرّف هذا المجلد مسارات Next.js. |
| `icons/` | مكونات الأيقونات؛ `icons/index.tsx` يجمع التصديرات للاستخدام المشترك. |

غالباً ما يقسم المكوّن المركب إلى مجلد ميزة: `index.tsx` يركب الواجهة، والملفات المجاورة تحوي أجزاءها أو بياناتها أو أنواعها. لذلك لا يعني كل ملف في `components/main/` أنه صفحة مستقلة.

## 6. الملفات المحورية وتدفق كل منها

### الحالة والسياق

`src/context/instamall-store.tsx` هو المصدر المشترك لحالة InstaMall. يوفّر `useInstaMallStore()` للصفحات والمكونات ويحتفظ ببيانات مثل المستخدم الحالي والمنتجات والمتاجر والطلبات ومؤشرات الإدارة والبائع والسلة.

عند بدء التطبيق يستعيد الجلسة المحفوظة، ثم يحمّل البيانات العامة والبيانات المسموح بها بحسب دور المستخدم. كما ينفذ إجراءات تسجيل الدخول والتسجيل وتحديث بيانات المستخدم والطلب وتأكيد الطلب الفرعي وإدارة المنتجات. أخطاء API تُعرض للواجهة عبر حالة الخطأ والتنبيه.

`src/context/theme-context.tsx` يدير الثيم. مزوّدو السياق الفعليون يُركّبون في `[locale]/layout.tsx` كي تكون متاحة للمسارات التابعة له.

### الاتصال بالخلفية

| الملف | ما يقوم به |
|---|---|
| `src/lib/api/client.ts` | عميل HTTP عام مبني على `fetch`؛ يرسل الطلبات، يقرأ الاستجابات، ويحوّل استجابات الخطأ إلى أخطاء قابلة للمعالجة. |
| `src/lib/api/collection-adapter.ts` | محوّل مشترك لتوحيد جلب مجموعات DTO وتحويل عناصرها إلى نماذج واجهة. |
| `src/lib/api/instamall/index.ts` | عمليات InstaMall: المصادقة، الملف الشخصي، المنتجات، المتاجر، الطلبات، وإحصاءات الإدارة والبائع. يضيف رمز Bearer ويستدعي المحوّلات. |
| `src/lib/api/instamall/types.ts` | تعريف أشكال DTOs والطلبات والاستجابات كما تتعامل معها واجهة API. |
| `src/lib/api/instamall/mappers.ts` | تحويل DTOs إلى النماذج التي تعرضها الواجهة، واشتقاق بعض قيم العرض مثل رقم الطلب والوقت المتبقي. |
| `src/lib/api/instamall/session.ts` | قراءة وحفظ رمز الجلسة وبيانات المستخدم في `localStorage`، وبناء عنوان API. |
| `src/lib/auth-routes.ts` | بناء روابط موحدة لتسجيل الدخول والتسجيل ونوع الحساب. |
| `src/types/instamall.ts` | أنواع بيانات الواجهة؛ تبقى منفصلة عن أسماء وحقول DTO الخلفية. |

تُرسل الواجهة الطلب إلى `/api/*`. في `next.config.ts` تُعاد كتابة هذه الطلبات إلى `BACKEND_API_URL`؛ والقيمة الافتراضية في الإعداد هي `http://127.0.0.1:4000`. بذلك لا تضع مكونات العرض عنوان الخلفية أو تفاصيل HTTP بداخلها.

### مثال تفاعل: طلبات البائع

1. `shop/page.tsx` يقرأ الطلبات ومؤشرات البائع من `useInstaMallStore()` ويرسل دالة تغيير الحالة إلى `ShopOrdersTable`.
2. `components/shop/shop-orders-table.tsx` يعرض الجدول ومرشحاته وترقيمه، وينادي callback عند التأكيد أو الرفض. لا يتصل الجدول بالخادم بنفسه.
3. الصفحة تستدعي `confirmSubOrder` أو `rejectSubOrder` من السياق.
4. `instamall-store.tsx` يستدعي `updateSubOrderStatus` في `lib/api/instamall/index.ts`.
5. عملية API تمر عبر `client.ts`، ثم تتحدث الحالة المحلية في حال النجاح؛ عند الفشل يُعرض الخطأ ولا يُقدَّم نجاح وهمي.

## 7. اللغة والتنسيق

### اللغات والاتجاه

- `src/i18n/routing.ts`: يعرّف اللغتين `ar` و`en`، والعربية افتراضية، مع بادئة عند الحاجة فقط.
- `src/i18n/navigation.ts`: أدوات التنقل المحلية المستخدمة بدلاً من أدوات الروابط المعتادة في مناطق الترجمة.
- `src/i18n/request.ts`: اختيار رسائل اللغة لطلبات Next.js.
- `src/i18n/languages.ts`: معلومات اللغة، ومنها تحديد اتجاه RTL.
- `src/proxy.ts`: يستخدم `next-intl` لتوجيه المسارات حسب اللغة.
- `src/messages/ar.json` و`src/messages/en.json`: قواميس النصوص المترجمة.

`[locale]/layout.tsx` يضبط `lang` و`dir` ويوفر سياق الترجمة. التغطية ليست مكتملة في كل صفحات القالب، لذا يجب التحقق من القاموس ومن الصفحة عند تعديل نصوص الواجهة.

### الأنماط

`src/app/globals.css` يحتوي على الأنماط العامة ورموز Tailwind والثيم الداكن وبعض تخصيصات المكتبات. يستخدم المشروع Tailwind CSS v4 ولا يعتمد على ملف `tailwind.config` تقليدي. نظراً لدعم RTL، اتبع الخصائص المنطقية مثل `ms/me` و`ps/pe` و`start/end` بدلاً من تثبيت الاتجاه إلى اليمين أو اليسار.

## 8. أنواع البيانات والأدوات

- `hooks/`: hooks عامة قابلة لإعادة الاستخدام، مثل إدارة الترقيم للشاشات الجدولية.
- `types/`: أنواع نموذج الواجهة؛ لا تضع فيها منطق الاتصال.
- `utils/`: دوال مستقلة صغيرة، مثل تنسيق سعر الليرة السورية، دمج أصناف CSS، الترقيم، ومعالجة رسائل الأخطاء.
- `mock/`: موضع مخصص لبيانات العرض التجريبي؛ لا تعتبر بياناته مصدراً لبيانات الإنتاج.
- `public/`: صور وأصول ثابتة يمكن للواجهة الإشارة إليها بمسار عام.

## 9. ما هو تطبيق وما هو من القالب؟

واجهات المتجر والبائع والإدارة وعملياتها المتصلة بـ `useInstaMallStore()` هي أجزاء InstaMall. في المقابل، بعض صفحات `admin/` ووحدات `components/main/` و`components/others/` و`layout/` أمثلة أو أجزاء من قالب TailAdmin. وجود الصفحة في المشروع لا يعني أن لها endpoint حقيقياً أو أنها مكتملة كميزة إنتاجية؛ تحقق من مصدر بياناتها وسلوكها قبل الاعتماد عليها.

يجب أن تظل صلاحيات الوصول الحقيقية مفروضة في الخلفية. إخفاء رابط أو صفحة في الواجهة ليس بديلاً عن التحقق الخادمي. كما لا ينبغي عرض حقول لا توفرها API أو لا تسمح سياسة الخصوصية بعرضها.

## 10. من أين أبدأ عند التعديل؟

1. **تغيير صفحة أو مسار:** ابدأ من `src/app/[locale]/...` وحدد أقرب `layout.tsx`.
2. **تغيير مكوّن متكرر:** ابحث في `components/ui/` أو مجلد الميزة المناسب قبل إنشاء مكوّن جديد.
3. **تغيير بيانات أو إجراء:** تتبّع الاستدعاء من الصفحة إلى `useInstaMallStore()` ثم `lib/api/instamall/`؛ عدّل DTO وmapper والنموذج فقط عند الحاجة.
4. **إضافة نص مترجم:** استخدم `next-intl` وأضف النص إلى ملفات الرسائل المناسبة بدلاً من تثبيت النص في مكوّن مترجم.
5. **التحقق محلياً:** شغّل من مجلد `web` الأوامر `npm run lint` ثم `npm run build`.

للتفاصيل المتعلقة بحدود تغييرات الواجهة ومعايير إعادة الهيكلة، راجع `frontend-refactor-spec.md`. ولأهداف النظام ومتطلباته الوظيفية، راجع `sad.md`.
